# What ARES can support

ARES supports exploring how DEM-scale topography affects an illustrative Mars route. It offers traceable terrain calculations, comparable route objectives and explicit evidence gaps. It is a research and educational prototype; it cannot certify astronaut or rover safety.

| Boundary | Implication for a judge or planner | Evidence / next step |
| --- | --- | --- |
| DEM spatial resolution | The original derivative has approximately 462 m equatorial pixels. A 4 ppd reference is much coarser. Neither resolves rocks, cracks, narrow gaps or human-scale obstacles. | Check the configured input and [methodology](METHODOLOGY.md); add independently sourced higher-resolution terrain where appropriate. |
| Slope-screening assumptions | LOW/MODERATE/HIGH/EXTREME describe estimated slope at the DEM scale. The 5/15/25° thresholds and penalties have no vehicle- or astronaut-specific calibration. EXTREME remains traversable at finite cost. | Use classes as explanatory categories; assess threshold sensitivity and independently calibrate mobility before stronger claims. |
| Physical terrain uncertainty | Gridded MOLA values can be interpolated. Horizontal CRS text does not establish the derivative's precise vertical datum or latitude-processing history. | Preserve [provenance questions](DATASET_PROVENANCE.md) and obtain the original acquisition/conversion record. |
| Missing observations | A masked or unsupported native sample is unavailable. A valid coarse average can omit masked native pixels. | Keep gaps visible; global availability does not imply continuously observed native terrain. |
| Surface-distance model | A 3,389.5 km sphere approximates geographic lengths; elevation change, terrain-following distance and movement dynamics are not included. | Interpret distance as geometric model output. |
| Vehicle mobility | Wheel geometry, soil mechanics, traction, slippage, energy use and vehicle-specific terrain limits are absent. | Add and validate a specified mobility model separately; slope classes cannot substitute for it. |
| Astronaut survival / EVA | There is no life-support budget, oxygen/consumables model, radiation model, environmental forecast, thermal/illumination schedule or astronaut-specific exposure limit. | ARES addresses terrain intelligence within the [selected Martian Map challenge](CHALLENGE_ALIGNMENT.md), not a complete survival-planning system. |
| Global resolution | The global graph uses 1° averages, roughly 59 km north–south. Small hazards disappear during aggregation. | Treat global output as a coarse corridor; use finer documented inputs and continuous checks for stronger planning scope. |
| Local refinement | At most eight selected windows are inspected. Some may be skipped or unavailable. Coarse risk is not rescored over a continuously surveyed refined line. | Read the window accounting and retain coarse-versus-local metric labels. |
| Modeled route cost | Terrain-weighted A* optimizes distance times illustrative class penalties. The separate risk index counts classified path cells. | Neither is measured travel time, energy, failure probability or operational mission risk; see [algorithms](ROUTING_ALGORITHMS.md). |
| Software versus science validation | Tests can show correct implementation of declared assumptions. A transformed MOLA product matching another MOLA product is not independent observational ground truth. | Keep [evidence layers](SCIENTIFIC_VALIDATION.md) separate and obtain independent terrain controls with stated tolerances. |
| Full original DEM evidence | The owner recorded a full-file hash and two regional smoke passes. This workspace does not contain that original raster. | Do not generalize those passes to full-planet accuracy, global coverage completeness, cold-load performance or independent execution here. |
| External imagery / hardware | NASA Trek tiles need an external service. WebGL depends on browser/hardware support; the application supplies a 2D fallback. | Browser checks with isolated tiles do not establish external service uptime or every-device compatibility. |
| Competition readiness | Selecting a challenge and preparing a demonstration do not establish eligibility, submission compliance or an award. | Verify the actual event's current instructions and rights conditions using [competition readiness](COMPETITION_READINESS.md). |

A useful demonstration identifies the input, states its resolution, compares modeled objectives and shows where observations are missing. It can establish that ARES makes these assumptions inspectable while leaving physical mission decisions to evidence and models beyond its present scope.
